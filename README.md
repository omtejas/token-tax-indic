# The Token Tax
### Measuring tokenizer inefficiency and inference cost across Indian languages

A reproducible study of equivalent English, Hindi, Kannada, Tamil, and Telugu text. It separates tokenizer-only analysis from model-native GPU inference measurements.

> **Research integrity:** no benchmark result is claimed until generated by a recorded run on actual hardware.

## Research questions
1. How do token counts differ across languages and tokenizer families on aligned parallel sentences?
2. How does tokenization change context occupancy and equivalent sentence capacity?
3. For compatible native tokenizer–model pairs, how do prompt length, prefill latency, throughput, and peak GPU memory differ?
4. How sensitive are results to Unicode normalization and input length?

## Method
- Dataset: FLORES-200 consolidated Parquet mirror (`yash9439/flores200`), with English, Hindi, Kannada, Tamil and Telugu columns aligned in the same row. Review its CC-BY-SA 4.0 terms and cite NLLB/FLORES. The loader validates sentence IDs before joining.
- Tokenizers: five public Hugging Face tokenizers configured in `configs/experiment.yaml`. Verify revisions, licenses and language coverage before the final run.
- GPU: model and native tokenizer pair only. Cross-model differences are system-level, not isolated tokenizer causal effects.
- Ablations: Unicode normalization (none/NFC) and sentence length groups.
- Statistics: paired sentence-level token ratios/differences with bootstrap confidence intervals. Do not assign random seeds to deterministic token counts.
- Context loss: percentage fewer complete parallel sentences that fit in a fixed 8,192-token budget versus English, under the same tokenizer.

## Windows setup
Python 3.14 is installed on the target PC. Current PyTorch Windows documentation lists Python 3.10–3.14 support; use a clean virtual environment and install a CUDA-enabled wheel from the official selector.

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
pip install -e .
python -m pytest
python -m token_tax.cli gpu-info
```

If an optional dependency has no Python 3.14 wheel in your environment, use Python 3.12 in a separate environment; do not alter system Python.

Install PyTorch using the official selector: https://pytorch.org/get-started/locally/ . The CUDA version printed by `nvidia-smi` is the driver's supported runtime level; it is not an instruction to install the CUDA Toolkit separately.

## One-command Windows workflow
Run these from PowerShell in the cloned repository:
```powershell
.\\setup_windows.ps1
.\\run_experiments.ps1
.\\run_dashboard.ps1
```
The setup script creates an isolated Python 3.14 environment, installs dependencies, runs tests and checks CUDA. The experiment script runs the five-tokenizer study followed by the native Qwen GPU prefill benchmark. The dashboard opens locally in your browser.

For individual stages:
```powershell
.\\.venv\\Scripts\\python.exe -m token_tax.cli tokenize --config configs/experiment.yaml
.\\.venv\\Scripts\\python.exe -m token_tax.cli gpu-benchmark --config configs/experiment.yaml --model-config configs/model.yaml
.\\.venv\\Scripts\\python.exe -m token_tax.cli failure-analysis --input results\\tokenizer_metrics_<run>.csv
```

The initial hardware target is an NVIDIA GeForce RTX 4050 Laptop GPU with 6 GB VRAM. Keep VRAM headroom for Windows; start at batch size 1. Actual model choice, precision and memory footprint must be verified on-device.

## Reproducibility
Each run should retain its git revision, exact dataset/model/tokenizer revisions, config, software versions, GPU name/VRAM, precision, batch size, input lengths, warm-up and timed trial counts. Label metrics as measured, estimated or unavailable. Energy metrics are omitted unless reliable telemetry exists. API cost is simulated only with a declared matching model/tokenizer rate.

## Limitations
Token counts are not translation quality. Different model families differ in architecture and training. GPU timings depend on hardware, drivers, thermals and background load. KV-cache estimates must use exact attention architecture (including GQA/MQA) and be distinguished from measured memory.
